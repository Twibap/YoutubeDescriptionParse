# 테스트 구성

이 문서는 `tests/`에 있는 테스트 코드가 검증하는 동작을 파일별로 정리한다. 현재 테스트는 6개 파일의 테스트 함수 64개로 구성된다. `pytest.mark.parametrize`가 적용된 함수는 입력값별로 여러 테스트 사례로 실행되므로 실제 실행 사례 수는 이보다 많다.

모든 테스트는 외부 네트워크에 의존하지 않는다. YouTube 관련 테스트는 가짜 메타데이터 소스나 고정 응답을 사용하는 `yt-dlp` 추출기로 수집 동작을 확인한다.

## 설명 파서

`tests/test_parser.py`에는 테스트 함수 21개가 있다.

- 한 줄짜리 실제 설명에서 식당을 추출하고 뒤의 도서 광고는 제외한다.
- 하나의 블록이나 한 줄에 여러 식당이 있으면 등장 순서대로 추출한다.
- 광고나 BGM 같은 비식당 구간이 끝난 뒤 새 `[식당정보]` 마커부터 추출을 재개한다.
- 일반 URL, Markdown 링크, 꺾쇠 링크에서 지도 URL을 추출한다.
- URL 내부의 괄호와 중첩 괄호를 보존한다.
- 잘못된 URL은 `invalid_url` 검토 대상으로 분리하고 다음 마커까지 파싱을 중단한다.
- 포트, 대문자 HTTPS, IP 주소가 포함된 유효한 HTTP URL을 보존한다.
- 식당명과 주소 내부의 공백 및 줄바꿈을 보존한다.
- 도로명, 지번, 특별자치도, 시·구 생략형 등 여러 주소 형식을 인식한다.
- `서울 국수집`처럼 지역명으로 시작하는 식당명을 주소로 오인하지 않는다.
- 소개나 설명 문장처럼 보이는 이름은 `ambiguous_fields` 검토 대상으로 분류한다.
- `소개식당`처럼 단어 일부에 소개 문구가 들어간 정상 상호는 허용한다.
- 동·리·가 뒤에 도로명이 오는 축약 주소를 인식한다.
- 광고, 촬영 정보, BGM, 이메일, 책 구매 등 메타데이터 구간에서 추출을 종료한다.
- 동일 식당이 반복 언급되어도 병합하지 않고 서로 다른 `mention_id`를 부여한다.
- 빈 설명, 마커 누락, 필드 누락, 애매한 내용은 검토 데이터로 보존한다.
- 마지막 식당의 URL이 없으면 앞 식당과 분리해 `missing_url`로 기록한다.
- 깨진 패턴 이후의 내용을 건너뛰고 다음 식당 마커부터 복구한다.
- 한 줄 중간에 이메일이 나오면 식당 블록을 종료한다.
- 공백이 들어간 `[ 식당 정보 ]` 마커를 지원한다.
- Windows 줄바꿈인 CRLF를 지원한다.

## YouTube 재생목록과 영상 수집

`tests/test_youtube.py`에는 테스트 함수 13개가 있다.

- 재생목록 ID, YouTube URL, Music YouTube URL 등을 표준 URL로 정규화한다.
- 빈 값, 잘못된 ID, 외부 도메인, 사용자 정보나 포트가 포함된 URL 등을 거부한다.
- 영상을 다운로드하지 않고 평면 재생목록 메타데이터만 수집한다.
- 영상 제목, URL, 재생목록 위치와 설명 원문을 정확히 보존한다.
- 설명이 없는 영상은 빈 설명을 가진 정상 영상으로 처리한다.
- 재생 가능한 포맷이 없어도 실제 `yt-dlp` 추출기에서 설명 원문을 보존한다.
- 비공개 영상을 HTML의 대체 제목으로 정상 영상처럼 처리하지 않는다.
- 비공개 영상은 오류 로그에 남기고 성공 캐시에는 포함하지 않는다.
- 잘못된 재생목록 메타데이터 구조, ID와 항목을 오류로 처리한다.
- 잘못된 영상 ID, 제목, 설명과 URL 메타데이터를 오류로 처리한다.
- 추출기 오류를 파이프라인이 기록할 수 있도록 상위로 전달한다.
- `yt-dlp`가 없어도 파서와 소스 객체를 만들 수 있고, 실제 수집 시 설치 안내를 제공한다.
- 잘못된 입력은 네트워크 클라이언트를 만들기 전에 거부한다.

## YouTube 채널 수집

`tests/test_channel.py`에는 테스트 함수 15개가 있다.

- 채널 핸들 입력을 항상 일반 동영상 `/videos` 탭으로 정규화한다.
- 채널 ID URL의 대상 채널 식별자를 보존한다.
- 한글 등 유니코드 핸들을 일관된 인코딩 URL로 정규화한다.
- 외부 도메인, Shorts·라이브 탭, 영상 URL과 잘못된 채널 ID를 거부한다.
- 다운로드 없이 채널의 일반 동영상 목록만 요청한다.
- 탭 전용 ID보다 `channel_id`를 우선 사용한다.
- `channel_id`가 없으면 유효한 메타데이터 ID를 사용한다.
- 영상이 없는 채널 탭도 정상적인 빈 목록으로 처리한다.
- 유효한 채널 식별자가 없는 메타데이터를 거부한다.
- 채널 ID로 요청했는데 다른 채널의 메타데이터가 반환되면 거부한다.
- 채널 영상의 설명 원문과 출처 필드를 보존한다.
- 잘못된 `channel:` 출처 ID를 클라이언트 생성 전에 거부한다.
- 개별 영상 소유자가 달라도 목록을 가져온 채널을 출처로 사용한다.
- 채널 수집 결과가 CSV 열과 `mention_id` 계약을 유지하고, 원문 캐시에서 수집을 재개한다.
- 충돌하는 채널 ID 메타데이터가 캐시를 오염시키지 않도록 한다.

## 수집 파이프라인

`tests/test_pipeline.py`에는 테스트 함수 8개가 있다.

- 영상 수집, JSONL 저장, UTF-8 BOM CSV 출력과 캐시 기반 재개를 확인한다.
- 재생목록 안의 중복 영상은 `refresh`를 사용해도 한 번만 수집한다.
- 실패한 영상은 오류 로그에 기록하고, 재시도할 때 성공한 영상을 다시 가져오지 않는다.
- `KeyboardInterrupt` 발생 시점까지 체크포인트와 결과물을 보존한다.
- 새로고침은 기존 원문과 식당 언급을 교체하되 중복을 만들지 않는다.
- 같은 영상이 서로 다른 재생목록에 있으면 두 출처를 각각 보존한다.
- `limit`은 목록 앞쪽 항목만 선택하며, 동일 캐시 재파싱은 반복 실행해도 같은 결과를 만든다.
- 손상된 캐시는 덮어쓰지 않고 파일과 줄 번호를 포함한 오류로 보고한다.

## 명령행 인터페이스

`tests/test_cli.py`에는 테스트 함수 5개가 있다.

- `parse` 명령은 네트워크 수집기를 만들지 않고 원문 캐시만으로 동작한다.
- 입력 파일이 없으면 사용자용 오류 메시지와 종료 코드 2를 반환한다.
- 일부 영상 수집이 실패하면 종료 코드 1과 오류 파일 경로를 출력한다.
- 사용자가 수집을 중단하면 종료 코드 130과 중단 메시지를 출력한다.
- `--limit`에 0, 음수나 문자열이 들어오면 명령행 오류로 거부한다.

## 저장소

`tests/test_storage.py`에는 테스트 함수 2개가 있다.

- 원자적 저장 중 직렬화가 실패해도 기존 파일을 보존하고 임시 파일을 남기지 않는다.
- `playlist_index`가 불리언, 음수나 문자열이면 원문 캐시를 읽을 때 거부한다.

## 실행 방법

Windows PowerShell과 macOS 터미널에서 다음 명령을 동일하게 사용한다.

```text
uv sync --frozen
uv run --frozen pytest
```

전체 개발 검증은 다음 순서로 실행한다.

```text
uv run --frozen pytest
uv run --frozen ruff check .
uv run --frozen ruff format --check .
uv build
```
